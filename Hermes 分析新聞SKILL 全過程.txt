+# Financial News Investigation
+
+Verify whether a news story is true — and specifically whether its **numeric claim** (usually "X salary → Y wealth over Z years") is *mathematically plausible*. The trap: verifying the person/book is real but leaving the core numbers assumed. You must quantify AND verify the math against actual market data before declaring it credible.
+
+## When to Use
+- User shares a news article and asks "is this true?" / "可信嗎" — especially financial, salary-to-wealth, dividend, or compound-growth claims.
+- The story hinges on a number (annual dividend, portfolio value, years to reach X).
+
+## Procedure
+
+### 1. Extract the article
+Read the full text (web_extract → fallback browser/`curl`). Pull every numeric claim into a table: timeline of events + figures (year → event → amount).
+
+### 2. Verify the *story* is real (person/book/sources)
+Confirm the subject, book, social account, and multi-source coverage exist (search listings like 誠品/Kingstone/Facebook/YouTube; find ≥1 independent outlet reprinting it). Flag self-reported figures as "作者自報 / not audited."
+
+### 3. Build a quantitative model of the core claim
+Reconstruct the compounding path. Use:
+- FV = PMT × [((1+r)ⁿ − 1)/r] for annual-investment scenarios (year-end, start=0).
+- CAGR = (end/start)^(1/years) − 1.
+Estimate realistic contribution range from the subject's income (e.g. Taiwan substitute teacher ≈ 45–60万/yr, save ~40–70万).
+
+### 4. VERIFY the key numeric assumption against REAL data ← THE KEY STEP
+Do NOT assume a return rate like "12–14%/year" is plausible — prove it. Pull actual historical returns for the relevant market/index and the subject's likely holdings:
+- Taiwan: `^TWII` (加權報酬指數, includes dividends) beats plain TAIEX; fetch daily closes from Yahoo Finance API (`query1.finance.yahoo.com/v8/finance/chart/%5ETWII`) and compute CAGR per period. Check key stocks separately (e.g. `2330.TW`).
+- Compare the story's implied return to what the market *actually* delivered in those exact years. Note if it required picking winners (concentration) vs. broad index.
+
+### 5. Reverse-calculate "what would it take?"
+Answer: given realistic savings, what return is needed? Given a target, how much must be saved per year? This exposes whether the story needs luck/concentration/high-savings or just happened.
+
+### 6. Assess plausibility + flag risks
+Score: person真实性 / narrative coherence / number precision / replicability (★ scale). List risks: survivorship bias, return-rate-not-guaranteed, "高股息≠高報酬", concentration risk, unaudited self-reported figures.
+
+## Deliverable (make it COMPLETE — don't wait to be asked)
+A report that includes ALL of:
+- Original claims table + verification results per claim.
+- The quantitative model + reverse-calculation tables.
+- **Charts** for the data-heavy parts (SVG-in-HTML bar/column charts work well).
+- **References/sources appendix** with URLs (register sources at retrieval time; don't reconstruct from memory — see `grounded-citations`).
+- Convert to **PDF** when data-heavy: write HTML → `libreoffice --headless --convert-to pdf`.
+

+
+## Pitfalls
+- Verifying the *person* but not the *math* → story looks true, claim may be optimistic.
+- Assuming "12–14%/year" without checking what the market actually returned in those years.
+- Listing sources from memory at the end instead of registering them as you retrieve.
+- Delivering a text-only report for data-heavy financial claims (missing charts/PDF).

+# Financial News Investigation
+
+Verify whether a news story is true — and specifically whether its **numeric claim** (usually "X salary → Y wealth over Z years") is *mathematically plausible*. The trap: verifying the person/book is real but leaving the core numbers assumed. You must quantify AND verify the math against actual market data before declaring it credible.
+
+## When to Use
+- User shares a news article and asks "is this true?" / "可信嗎" — especially financial, salary-to-wealth, dividend, or compound-growth claims.
+- The story hinges on a number (annual dividend, portfolio value, years to reach X).
+
+## Procedure
+
+### 1. Extract the article
+Read the full text (web_extract → fallback browser/`curl`). Pull every numeric claim into a table: timeline of events + figures (year → event → amount).
+
+### 2. Verify the *story* is real (person/book/sources)
+Confirm the subject, book, social account, and multi-source coverage exist (search listings like 誠品/Kingstone/Facebook/YouTube; find ≥1 independent outlet reprinting it). Flag self-reported figures as "作者自報 / not audited."
+
+### 3. Build a quantitative model of the core claim
+Reconstruct the compounding path. Use:
+- FV = PMT × [((1+r)ⁿ − 1)/r] for annual-investment scenarios (year-end, start=0).
+- CAGR = (end/start)^(1/years) − 1.
+Estimate realistic contribution range from the subject's income (e.g. Taiwan substitute teacher ≈ 45–60万/yr, save ~40–70万).
+
+### 4. VERIFY the key numeric assumption against REAL data ← THE KEY STEP
+Do NOT assume a return rate like "12–14%/year" is plausible — prove it. Pull actual historical returns for the relevant market/index and the subject's likely holdings:
+- Taiwan: `^TWII` (加權報酬指數, includes dividends) beats plain TAIEX; fetch daily closes from Yahoo Finance API (`query1.finance.yahoo.com/v8/finance/chart/%5ETWII`) and compute CAGR per period. Check key stocks separately (e.g. `2330.TW`).
+- Compare the story's implied return to what the market *actually* delivered in those exact years. Note if it required picking winners (concentration) vs. broad index.
+
+### 5. Reverse-calculate "what would it take?"
+Answer: given realistic savings, what return is needed? Given a target, how much must be saved per year? This exposes whether the story needs luck/concentration/high-savings or just happened.
+
+### 6. Assess plausibility + flag risks
+Score: person真实性 / narrative coherence / number precision / replicability (★ scale). List risks: survivorship bias, return-rate-not-guaranteed, "高股息≠高報酬", concentration risk, unaudited self-reported figures.
+
+## Deliverable (make it COMPLETE — don't wait to be asked)
+A report that includes ALL of:
+- Original claims table + verification results per claim.
+- The quantitative model + reverse-calculation tables.
+- **Charts** for the data-heavy parts (SVG-in-HTML bar/column charts work well).
+- **References/sources appendix** with URLs (register sources at retrieval time; don't reconstruct from memory — see `grounded-citations`).
+- Convert to **PDF** when data-heavy: write HTML → `libreoffice --headless --convert-to pdf`.
+
+## User preference notes
+- Clean report style: references at the end, NOT Perplexity-style inline `[1][2]` markers. (`grounded-citations` skill exists but its inline style is heavier than this user wants for reports.)
+- Verify numbers against real data up front — the single most common gap is assuming a return rate instead of proving it.
+
+## Pitfalls
+- Verifying the *person* but not the *math* → story looks true, claim may be optimistic.
+- Assuming "12–14%/year" without checking what the market actually returned in those years.
+- Listing sources from memory at the end instead of registering them as you retrieve.
+- Delivering a text-only report for data-heavy financial claims (missing charts/PDF).
